# Saved receipt library

`/receipts` now reads saved company records through `GET /api/receipts/library`. The old page generated50random demo rows and displayed hardcoded counts/trends. It also removed a row locally after a supposed delete regardless of the server outcome; the actual detail route does not implement that deletion. The real library exposes View and CSV, with Upload on its existing page. Receipt linking/deletion/OCR retain their separate native flows; this library makes no mutation claim.

`receiptLibraryService` filters by the trusted selected company and reads only filenames, size, upload date, amount, currency, merchant and status. It maps a display projection with no raw document metadata, paths, URLs, OCR, actor/company lists or linked transaction pointers. Filename is the original uploaded name where recorded. Unknown currency remains null; zero remains zero. Counts come from the exact returned company set: total, literal matched/unmatched, processing/error, matched divided by total. Processing/error are not labeled unmatched. No historical trend is invented.

The native endpoint reuses fresh `calendarCompany` membership and no-store, with fixed error text. Existing receipt APIs, statistics, exports, matcher, models and shared membership/auth/lease predicates are unchanged. The list loads the complete projected company set, filters literally in the browser and paginates10rows. This is not a server-paginated library; large libraries remain a scaling follow-up. The date filter and display use Japan time. Currency is the saved code, never chosen from the UI language. Amount filters compare recorded numbers without conversion; a currency filter can separate them.

Search/filter changes reset pagination, and shrinking results clamp it. Actor/company changes synchronously clear rows/counts/errors and reset filters. Reads wait for session acceptance, with generation/scope checks discarding late results. Failures show retry rather than demo/empty success. An empty company displays actual zero counts. CSV downloads only the filtered display rows, preserving zero, fractions and empty unknown currencies; formula-leading text is emitted as text, while numeric negatives remain numeric. Blob URLs are released after the click. No server export or financial write is performed.

New guards: company-filtered read/projection, stale-response checks and CSV text neutralization. These require scoped review; shared company/auth predicates are not modified. Caller map: list → new library GET → display service → Receipt; View → actual receipt detail → existing whitelisted evidence reader; Navi receipt tools remain unchanged. The existing mock `useReceipts` composable is not used by this page and is not certified as a real data source by this change.

`finance-receipt-library-integration.cjs` runs in the owned company-business fixture. Its initial native library request fails on the old compiled app, then checks projection/counts, real saved values, company overrides, current membership/roles/revocation/inactive companies, parallel company reads and unchanged financial snapshots. The optional installed-Chrome module checks real rows/statistics, filtering and pagination, currency/zero, actual detail navigation, CSV bytes, error/retry/empty and delayed cross-company replies. No model is needed for this UI/read increment. No production data, bank or business send is used.
