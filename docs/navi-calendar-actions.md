# Company Navi calendar actions

Self-mapped (FOLD). Company Navi now has four invoice/calendar record reads, `get_company_action_status` and `update_company_calendar_entry`. The update covers native title, amount, currency, dueDate, type, status, category, recurrence and notes; bank-transfer details and source/organization fields are outside this tool. The normal form retains its existing bankTransfer field. No create/delete, bank payment, issuer-contract change or invoice write is added.

Native PUT /api/payments/:id -> fresh calendarCompany -> updateCompanyCalendarEntry. Frozen company worker action -> existing working/job scope -> strict supplied tool schema -> durable company action claim -> working recheck -> the same updateCompanyCalendarEntry -> marker and receipt -> working recheck. The same native field selection, number cast, noon-UTC dates, schema validation, root company/suppression restriction and first settledAt ($min) are retained. Saved paid/completed is internal state; no bank confirmation or second ledger expense is created.

The model reads the relevant entry and its updatedAt before an explicitly requested edit, uses only the requested fields, then reads the actual result. Null legacy timestamps use an empty expectedUpdatedAt and an atomic null/missing match. An intervening dated change returns conflict. A discussion or hypothetical instruction saves nothing. The Japanese accountant role and configured Opus5.5/high are preserved; unsupported operations are described honestly.

Company action identities live in the existing separate conversation: owner/company/conversation/turn/slot plus canonical payload hash. Claiming slot and duplicate intent is atomic within that document. Reusing a slot with another meaning conflicts. Repeating an exact intent in the same turn returns its prior operation even from a new slot. The payment carries operationId, payload hash, accepted fields/values and time in the same mutation. Receipts expose outcome and native resource, never worker leases. No financial write occurs during reconciliation. A marker proves completion after a lost response; a missing marker on an expired claim stays unresolved and is not automatically executed again. Successor claims receive prior receipts and nextSlot. A later independent edit can supersede the single native marker, leaving an old unknown operation unresolved; it must not be presented as a failed or completed save without evidence.

AssistantConversation polls company state, displays the actual receipt, rereads the native payment and replaces an already loaded matching calendar row only if the original actor/company is still current. Late data cannot refresh a different company through this path. It does not reset an open calendar edit form. The introduction-film girl remains the Navi visual identity.

New customer-path guards: strict write arguments, snapshot comparison, frozen live job checks extended to effects, durable slot/intent identity and unknown-outcome handling, scope-checked result refresh. Independent review is required before release. Existing member/viewer policy and shared membership predicate are unchanged. Membership and financial mutation are not one database transaction; the existing narrow revocation race is not claimed eliminated. Timestamp concurrency has millisecond resolution; full operator/key/runtime custody and broad shared-guard reliability remain open.

Native synthetic regression preserves all earlier read-only assertions before deliberate mutation cases. It exercises zero, noon dates, preserved source/currency, first settlement, concurrent and cross-slot duplicate requests, stale snapshots, foreign/suppressed rows, role compatibility, lost receipts/unknown outcomes, lease reclaim and revoked membership. Installed Chrome drives a real save through native worker actions and observes the underlying calendar refresh. Synthetic worker answers are not a real-model evaluation or production reliability measurement. No production/bank/business send is required by those tests. All-feature G1-G4, invoice/transaction writers, F1 historical audit/F3 attribution, final review and deployed replay remain open.

A separate actual product-model evaluation runs Opus5.5/high through the existing TeachingWorker/MCP path and native APIs against owned synthetic data.
