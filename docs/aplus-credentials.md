# Aplus credential setup

The Ryzen 7 collector setup page has an **Aplus** section. Enter My APLUS ID and password, then choose **Save encrypted login**. Both fields clear after saving. To replace credentials, enter both fields again.

The credentials are stored in a local encrypted entry, with its wrapped data key held by OMF and its private key protected by Windows CurrentUser DPAPI. Other account credentials, pairing and mail settings are preserved. Setup routes bind to loopback and require the launch key and matching Host/Origin. Status responses expose only whether credentials are present, never the saved ID or password.

`secrets/aplus.sealed` binds this PC, OMF origin, owner and generation. Connect the PC once through OMF; access then resumes automatically across collector restarts. Saving requires that active connection. Only the `profile` key of `services.aplus` stays in the metadata blob. See [storage and recovery](amex-connector.md#storage-and-recovery) for revocation and the trusted-PC security boundary.

Saving does not open Aplus, submit a bank login, request verification, download statements or create a financial account. Those happen only when **確定明細を取得** is pressed in OMF for an Aplus account: the downloader signs in to My APLUS in a fresh Chrome profile with the saved login (the account's own `aplus-<id>` entry, or this single entry when it is the only Aplus account on the PC; with neither, a person signs in), downloads each finalized statement month OMF does not hold yet, captures the current unbilled page, and sends every file to OMF for review. My APLUS sends a four-digit SMS code for each statement download; the downloader has no SMS reader, so a person types the code in the Chrome window when the status shows 認証が必要 (one code per statement month per request; a code that never arrives fails the job without a second request, and the next press starts a new job).

Set **自動取得の会計期間** once on the account's card in OMF. Until explicitly changed, an existing account uses the latest accounting period recorded in its import history. OMF applies this period on the server; a downloader cannot override it. Purchases outside that period remain saved for individual review, including unbilled pages that span a year boundary. An already imported file keeps its original classification when an interrupted upload is retried. The setting does not post transactions or change the verified Yayoi account fields. With no saved or historical period, the page says the period check is not configured.

An offered statement month whose rendered payment total is empty is reported as unavailable; the downloader continues with other months and the unbilled page. Browser readiness follows the rendered statement and rows, so unrelated background requests do not hold up a completed page.

Validation: `npm test --prefix collector` checks the local setup boundary. After `npm run build`, run `node --import tsx scripts/collector-trusted-device-http.ts` for actual built HTTPS, Windows DPAPI, credential saving, migration, restart and disconnect acceptance. It owns a temporary database and private collector directory, uses synthetic credentials, and opens isolated Chrome with external requests blocked. It does not attach to a personal browser or use the production vault.
