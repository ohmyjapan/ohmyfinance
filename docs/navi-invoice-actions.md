# Company Navi invoice actions

Self-mapped FOLD. Invoice page/form -> native auth -> selected-company/live member -> shared invoice operation -> Invoice/owned transaction reference. Company Navi -> frozen worker/lease -> same operation -> atomic native marker -> durable turn receipt -> scoped invoice list refresh. No Article/Memo callers.

Navi can explicitly save invoice status, issueDate, dueDate, paidDate, taxRate, currency, notes and terms. It reads the saved invoice/timestamp first, edits requested fields and reads back the result. Discussion is read-only. Stored paid/sent dates/status are bookkeeping, not bank settlement or email delivery. A printed T number is not NTA verification. No automatic tax classification is established by changing a saved rate. Item, party, bank and linked-transaction edits remain unavailable to this tool. Native forms retain these fields.

Native POST/PUT/DELETE now use the existing fresh membership boundary; body company/creator/operator fields are not trusted. Creation captures company/actor, and invoice numbers count only that company. An existing same-company unique index handles collisions with409; no automatic number retry or AI create/delete is added. Linked transactions must belong to that company. Native PUT uses a business-field allowlist, schema validation and existing-snapshot comparison. Items retain explicit zero amounts; a rate-only change recomputes totals from the saved items, and zero rate stays zero. Existing aggregate Math.round tax treatment remains; this is not per-item/reduced-rate qualified invoice support. Native form dates keep the existing midnight Date conversion.

Company invoice actions reuse the existing calendar action journal, slot/payload identity, lease/member rechecks and no-blind-repeat recovery. Marker + domain update are atomic. A lost journal reply can recover from the invoice marker; a missing marker on an expired claim remains unresolved. A later edit can supersede a single marker; millisecond timestamps and non-transactional membership/domain checks remain explicit limitations. Original calendar receipts still recover from payment markers.

The existing accordion and introduction-film girl remain. Done invoice receipts trigger a matching actor/company list reload with current filters; delayed other-company or older-filter responses cannot replace the list. Open form buffers are preserved.

New customer-path guards: native write company/reference scope, ownership-field selection, field/date/tax/schema validation, derived-total snapshot comparison and invoice receipt/UI scope. Independent review is required before release. Shared membership roles are unchanged, including existing viewer eligibility. Full G1-G4, every-feature coverage, transaction actions, company learning/reasoning, F1 historical/shared-boundary audit, F3 disposition, full operator/key/runtime custody and final deployed proof remain open. Owned synthetic tests and model QA are not production reliability measurements.

Local verification uses the actual production build and owned synthetic Mongo/native APIs.19 units,7 company/native groups,8 company/Chrome groups and the original8 invoice-read groups pass. The original read defect harness now targets GET specifically because native write membership calls were added; its six original defect assertions are retained. Real Opus5.5/high runs through TeachingWorker/MCP: discussion writes nothing; an explicit Korean date/memo instruction reads/saves/rereads the actual invoice and yields a done receipt. Two initial calls are retained separately from the final two after clarifying that draft/date fields do not prove delivery or cash arrival. These are two scenarios, not four independent cases. The girl, native calendar/access/read sources and legacy action engine are unchanged. Independent review and deployed verification remain pending.
