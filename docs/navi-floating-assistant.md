# Floating Navi — 2026-10-20

Owner direction: replace the top-of-page assistant with the existing introduction-film girl as a floating character in the bottom-right corner, like the early Office assistant. This supersedes the earlier accordion presentation described in the dated Navi documents.

## Presentation and callers

- `layouts/default.vue` mounts `AssistantPanel` beside the page container, rather than before the slot. The collapsed control occupies no page space.
- `AssistantPanel.vue` anchors the character to the viewport's bottom-right safe area. Opening shows a nonmodal conversation above her. There is no backdrop, document scroll lock, automatic page scroll or focus trap. Minimize/Escape returns focus; normal page controls stay usable.
- `NaviAvatar.vue` adds a launcher size using the unchanged locally served `public/images/omf-navi-film.jpg`. No generated/replaced art or remote host. Conversation labels retain their existing small avatar.
- Owner size correction, 2026-10-20: the character is larger, 6rem on desktop and 5rem below640px viewport width (96px/80px at the existing root size). Dock, circular button and avatar inherit one launcher size. The chat's height allowance uses that size too, preserving header clearance; compact-height behavior still hides the launcher while the chat is open.
- The existing context, purchase/general selection, owner posting company, company selector, support diagnostics, histories, buffers, worker requests and action receipts remain. The posting-company explanation is expandable; the company selector's compact mode retains its accessible label, current selection, errors and native switch/reload behavior. It is not an ownership or financial-authority change.
- Desktop and mobile widths are bounded. Layers are page title rows10, Navi20, app header30, drawer40, page modals50. The default layout lifts only the header; it does not isolate main content or sink page modals. Measured header clearance keeps Navi's controls below the header too. Short viewports use the available visual viewport and compact composer. Context and diagnostics open from the compact header, with Escape returning focus to their buttons. The transcript retains actual content space, beyond its padding.
- Safe-area/keyboard offsets follow `visualViewport` resize/scroll and window resize; listeners are removed on unmount. A resize keeps the latest reply visible if the reader was already at the end; an earlier reading position is preserved.
- Purchase chat gets the same compact textarea sizing. Its server-checked posting-company label stays visible as an accessible disclosure; opening it shows the identical full explanation above the composer without covering Send. `PurchaseChat.vue` adds only the optional compact prop and this markup; its chat/history/save/research handlers and watchers are unchanged. Noncompact mode retains the original text and data attributes.
- Existing authentication and screen-lock visibility still hides the whole dock. `stores/assistant.ts`, `AssistantConversation.vue`, server/worker/model/action code are unchanged.

## Verification and limits

`scripts/finance-navi-floating-integration.cjs` runs installed Google Chrome and the actual built native app against its own disposable MongoDB and synthetic accounts. The browser leg checks collapsed position/size, no page displacement or scroll jump, open/minimize/buffer/navigation/reload, actual worker-queue reply, all six pages with raised title rows, mobile drawer navigation and notification-menu stacking, narrow/landscape geometry including390×360, transcript content after subtracting padding and actual reply visibility, composer/minimize hit tests, native company switch/history separation, support, lock and sign-out. The purchase-specific chat also runs actual claim/result and the same short-height reply/Send checks, plus its full posting-company explanation. A simulated `visualViewport.height` exercises a positive keyboard offset, both latest-reply and earlier-reading positions, and compact context/diagnostics controls. This simulation is not a physical phone keyboard test. No model/bank/mail/Slack/production calls or ledger writes. Screenshots are manually inspected; rectangle containment alone does not establish a usable layout.

Previous browser consumers use `data-assistant-dock`; the two old assertions requiring static content above the page now assert an anchored nonmodal window. Other conversation/privacy/save/retry assertions are retained. The owner-assistant browser starts on mapping, its current realm, rather than the company transactions page. Support diagnostics are opened inside Navi.

The company browser leg waits for the actual accepted server turn and cleared input before claiming a job; disabled input alone only means a POST is in flight. The owner browser waits for the authenticated launcher after navigation. Support UI tests launch their own installed Chrome/profile and await cleanup; they do not reuse or change the production collector's Windows ownership broker.

Self-mapped UI seam. Existing account-registration commit/review evidence is preserved separately. Synthetic UI checks are not production reliability measurements. This increment does not close the broader G1–G4 feature/privacy/official registry/observation limitations and adds no access/action guard.
